# タスク票の下書きを作るとき

OpenCode が、企画やリファクタのメモから、実装に渡せそうな作業を探してタスク票の下書きを作るときの決まり。下書きは Claude が読み、使えるものを番号付きで `.tasks/` に上げる（そのときにブランチを切る）。

## 読むもの

- `.tasks/context/` に置かれたメモ（Claude が企画メモからコピーしたもの）
- メモに出てくるファイルのコード。行番号はメモを書いた時点のものなので、`grep` で今の場所を探してから読む
- `.tasks/` の票と `git log`（同じ作業を二重に出さないため。済んだ票は消してあるので、済んだ作業はコミットで確かめる）

## 書くもの

- `.tasks/draft/<名前>.md` に、1つの作業につき1枚。名前は、作るとよいブランチ名の `/` を `-` にしたもの（例: `refactor-sdx-foo.md`）
- 形は `.opencode/task-template.md` に合わせる。そのうえで、冒頭に次の節を足す

```markdown
## 下書きのメモ

- 元にしたメモ: <`.tasks/context/` のファイルと見出し>
- 大きさ: S / M / L（S は1〜2ファイル・100行以内の変更）
- 難しさ: 1〜4（1: 変える箇所まで全部決まっている。2: 形は決まっていて置き換えは任せる。3: 期待値や中身を読んで出す。4: 何を変えるかの判断も要る）
- 確かめた事実: <コードを読んで確かめたこと。ファイルと行>
- 確かめていないこと: <推測のまま書いた所>
- ぶつかりそうな作業: <`git worktree list` と `git branch` で見えた、同じファイルを触っていそうなブランチ>
```

## 選び方

- 大きさ S か M のものを選ぶ。L は、段階に分けられるときだけ、最初の段階を1枚にする
- メモで「まだやらない」「寝かせる」「作り始める直前にやる」とされているものは出さない
- 作業中のブランチ（`git worktree list` に出るもの）と同じファイルを大きく触るものは出さない。出すなら「ぶつかりそうな作業」に書く
- 見た目や挙動を変えるもの（数値・文言・バランス）は出さない。リファクタ・テストの追加・明らかな不具合の修正に絞る
- 1回に作る下書きは、多くても5枚

## 書き方

- 票に書く事実は、コードを読んで確かめる。確かめていないことは「確かめていないこと」に書き、票の本文では断言しない
- 変更内容は、渡された人がこの会話を知らなくても作業できるように書く（目的・読むファイルと行範囲・守る書き方・完了条件）
- 守る書き方は、STYLE.md から、その作業に関わる決まりだけを写す（下書きを作るときは STYLE.md を読んでよい）

## やらないこと

- コードを変えること。書くのは `.tasks/draft/` の中だけ
- ブランチを作ること・切り替えること
- `.tasks/` 直下の票を書き換えること
